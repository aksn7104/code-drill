## 詳細

### D-01　全角（日本語入力のまま）で答えると不正解になる

- 現象：日本語入力がオンのまま「ｆ」「／」などの全角で答えると、正しい答えでも不正解になる
- 再現手順：正解が「a」の問題に、全角の「ａ」を入力する
- 期待：正解になる
- 実際：「不正解です。正解は「a」です。」と出る（TC-CLI-04 で確認）
- 原因：採点で、全角と半角を同じ文字として扱っていなかった（grading.py の `normalize`）
- 対応：入力と正解の両方を、全角・半角をそろえる変換（Unicode の NFKC 正規化）にかけてから比べる。全角スペースも半角スペースになる
- 確認：TC-GRD-06, 07, 08 / TC-CLI-04 が合格

### D-02　数字に似た特殊な文字で、エラーで止まる

- 現象：選択式の問題に「²」（上付きの2）や「①」を入力すると、エラーで止まる
- 再現手順：選択式の問題に「²」を入力する
- 期待：エラーで止まらない
- 実際：ValueError（`int('²')` が変換できない）。`isdigit()` が True を返すのに、`int()` が変換できない文字があるため
- 対応：D-01 の全角・半角をそろえる変換を、番号の判定より前に行う。「²」は「2」、「①」は「1」になる
- 確認：TC-GRD-09 が合格

### D-03　空の問題集、または形式が違う問題集で、エラーで止まる

- 現象：中身が空のファイルを読むと `TypeError`。問題のリストではない形式（先頭が辞書など）でも `TypeError` で止まる
- 再現手順：0バイトのYAMLを指定して `python drill.py` を起動する
- 期待：何が悪いかが分かる表示を出して終了する
- 実際：`object of type 'NoneType' has no len()`（TC-CLI-08）、`Population must be a sequence`（TC-CLI-09）
- 原因：読み込み後の形の検査がなかった（loader.py）
- 対応：空のファイルは0問として扱い、画面には「問題集に問題がありません」と出して終了する。リスト以外は、読み込みエラー（QuestionFileError）にして、書き方を伝える
- 確認：TC-LDR-05, 07 / TC-CLI-08, 09 が合格

### D-04　存在しない・書き方に誤りがある問題集で、エラーの画面が出る

- 現象：ファイル名の打ち間違い、YAMLの書き間違い（AIが作った問題集に起こりうる）で、Python のエラーの画面（Traceback）が出て、原因が読み取りにくい
- 再現手順：存在しないファイル名を指定して `python drill.py` を起動する
- 期待：「見つかりません」などの、原因が分かる1行を出して終了する
- 実際：`FileNotFoundError` などの Traceback が出る（TC-CLI-06, 07）
- 原因：読み込み時の例外を、使い手に伝わる形にしていなかった
- 対応：読み込みの例外を、問題集専用の例外（QuestionFileError）にそろえ、drill.py が1行の「エラー：…」にして標準エラーへ出し、終了コード1で終了する。`_language.yaml` の書き間違いも同様
- 確認：TC-LDR-04, 06, 12 / TC-CLI-06, 07 が合格

### D-05　入力の途中でやめると、エラーの画面が出る

- 現象：答えを入力する途中で Ctrl+C や Ctrl+D（入力の終わり）を押すと、Traceback が出る
- 再現手順：問題が出た状態で、何も入力せずに入力を終える
- 期待：「中断しました。」と出して終了する
- 実際：`EOFError` の Traceback（TC-CLI-10）
- 原因：入力待ちの中断を処理していなかった
- 対応：出題のループで `EOFError` と `KeyboardInterrupt` を受け取り、「中断しました。」を標準エラーへ出して、終了コード1で終了する
- 確認：TC-CLI-10 が合格
- 補足：中断までに答えた分は、段階4で「1問答えるたびに記録する」と決めたため、記録に残る（TC-CLI-14 で確認）

### D-06　code-drill 以外のフォルダから起動すると、見本が見つからない

- 現象：`python code-drill/drill.py` のように、別のフォルダから起動すると、見本の問題集が見つからない
- 再現手順：現在地を code-drill の外にして、`python /…/code-drill/drill.py` を起動する
- 期待：見本の問題集が出る
- 実際：`FileNotFoundError: 'questions/python/batting_01_variables.yaml'`（TC-CLI-05）
- 原因：既定の問題集の場所が、現在地からの相対パスだった
- 対応：既定の場所を、drill.py のあるフォルダを基準にした絶対パスにする（`Path(__file__).resolve().parent`）
- 確認：TC-CLI-05 が合格
- 補足：段階1〜3の確認は、すべて code-drill の中で行っていたため、気づけていなかった

### D-07　正解を引用符なしの NULL と書くと、不正解になる（修正済み：段階6-1）

- 現象：問題集に `answer: NULL` と書くと、YAML が `None` として読み込み、「NULL」と入力しても不正解になる。`yes`・`no`・`on`・`off` や、引用符のない数字も、文字ではなく別の型として読まれる
- 再現手順：`answer: NULL` の問題に「NULL」と入力する
- 当初の期待：正解になる
- 実際：不正解（TC-GRD-17。既知の不具合として登録していた）
- 原因：YAML の仕様。引用符のない値は、YAML が型を推測して読み込む。SQL の問題で NULL を答えさせる場面や、AI が作る問題集で起こりやすい
- 対応：読み込んだあとに答えの型を検査し、引用符のない書き方を検出して「answer を引用符で囲んでください」と知らせる。`python drill.py --check` と、出題の前の検査の両方で行う（`checker.py`）。誤りのある問題集は、出題せずに止める
- **期待の変更**：当初は「NULL と入力して正解になる」ことを期待していたが、対応は「間違った書き方を、出題の前に見つけて直させる」方針にした。理由は、①`None` を文字「None」として扱うと、「None」と入力した人が正解になってしまう ②`yes` を `True` として扱うなど、型ごとの例外が増えて、採点の決まりが分かりにくくなる ③引用符で囲めば、すべて同じ形で解決する、の3点。これに合わせて、TC-GRD-17 は「正解が `None` の問題でも、採点がエラーで落ちない」ことを確かめる形に変え、「検出」の確認は TC-CHK-08・09・10 と TC-CLI-32・35 が担当する
- 確認：TC-CHK-08・09・10、TC-CLI-32・35 が合格。検出の処理をわざと止めると、TC-CHK-08・09・10 が不合格になることも確認した
- 備考：数値の `answer: 1` は、採点側では文字に直すため正解になる（TC-GRD-16）が、`--check` では引用符を付けるよう求める（YAML の型の違いで混乱しないようにするため）

### D-08　必須の項目が欠けた問題で、回答後にエラーの画面が出る（修正済み：段階6-1）

- 現象：answer などの項目が欠けた問題が出題された場合、答えを入力した直後に Traceback が出る
- 再現手順：answer のない問題を含む問題集で起動し、答えを入力する
- 期待：読み込み時に、どの問題のどの項目が欠けているかを知らせて終了する
- 当初の実際：`KeyError: 'answer'`（TC-CLI-11。既知の不具合として登録していた）
- 原因：読み込み時に、項目の検査をしていない
- 対応：`--check` と同じ検査を、出題の前にも行う（`checker.py`）。誤りがあれば、問題を出す前に「エラー：問題集に誤りがあります」と、先頭の3件と `--check` の案内を表示して終了する
- 確認：TC-CLI-11・36、TC-CHK-03 が合格。出題前の検査をわざと外すと、TC-CLI-11・35・36 が不合格になることも確認した
