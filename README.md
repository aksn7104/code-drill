# code-drill（コード学習ドリル）

毎日2問、短いコード問題を出して、採点・解説・記録までを行う学習ツールです。
**AI がなくても動きます**（問題集は YAML のファイルです。AI は、問題集を増やすときだけ、任意で使います）。
学ぶ言語は、フォルダを足すだけで増やせます（Python と SQL の見本つき）。

## できること

- 1日2問（数は設定で変更）。空欄を埋める問題と、選択肢から選ぶ問題があります
- 学習する曜日と、言語の切り替え（例：2日に1度は SQL）を設定できます。休みの日は出題しません
- 答えていない問題は、翌日に出し直します
- 「もう1問」で、続きの問題を何問でも解けます。土曜は、長めの読解の問題が1問増えます
- 全問正解の学習日が続くと、難易度を上げる提案をします。自分で上げ下げもできます
- 単元を解き終えたら、Git に保存するコマンドを案内します
- 結果は CSV（`data/log.csv`）に記録します。自分のPCの中だけに保存されます
- 画面は2種類：文字（`drill.py`）、ウィンドウ（`gui.py`）。どちらも同じ部品を使うので、同じ動きです
- 決まった時刻の通知（任意）：画面の右下の通知、メール、スマホ（ntfy）
- 有料版には、ブラウザ版・キャラクター・称号・すごろくの地図・週間レポート・Notion 連携が付きます（「有料版のご案内」を見てください）

## 導入（はじめる）

### 1. 用意するもの

- **Python 3.10 以上**。コマンドの画面で `python --version` と打って、`Python 3.10` 以上と出れば大丈夫です（Windows で出ないときは、python.org から入れます。入れるとき「Add python.exe to PATH」にチェックを入れてください）
- このフォルダ（`code-drill`）。zip でもらったときは、展開してください

### 2. コマンドの画面を開く

- Windows：スタートメニューで「PowerShell」と入力して開きます。VS Code を使っているなら、フォルダを開いて、上のメニューの「ターミナル」→「新しいターミナル」でも同じです（フォルダの中で開くので、移動は要りません）
- PowerShell のときは、`cd` のあとにこのフォルダの場所を書いて移動します（例：ダウンロードに展開したなら、`cd Downloads\code-drill`）
- 今いる場所に `drill.py` があるか、`dir`（Windows）か `ls`（Mac・Linux）で確かめます

### 3. 部品を入れる（最初の1回だけ）

```
python -m pip install -r requirements.txt
```

外の部品は PyYAML だけです。ウィンドウ版（`gui.py`）には tkinter が必要です。python.org の Python には入っています。入っていない Python では、ウィンドウ版だけが使えません。

### 4. 動かす

```
python drill.py
```

今日の言語と、2問が出ます。答えを打ち込んで Enter を押してください。これだけで始められます。
設定ファイルがなくても、既定の設定で動きます（日曜は休みです）。

### 5. 動作を確かめる（任意）

```
python run_tests.py
```

全部の試験が通れば、あなたの環境で正しく動いています（「判定: 合格」と出ます）。

## 使い方（毎日の流れ）

### 2つの画面

| 画面 | 起動 | 向いている人 |
|---|---|---|
| 文字 | `python drill.py` | コマンドに慣れた人。いちばん軽い |
| ウィンドウ | `python gui.py` | ボタンで選びたい人 |

どの画面でも、中身は同じです（記録も共通です）。

### 1日の流れ

1. 起動すると、今日の言語・単元・難易度・周回が出ます
2. 問題に答えます。選択式は番号で、空欄式は文字で答えます（全角・半角、前後の空白は区別しません）
3. 答えるたびに、正解か不正解かと解説が出て、**その場で記録されます**（途中でやめても、答えた分は残ります）
4. 終わると、正解数が出ます
5. 全問正解の学習日が続いていれば、難易度を上げるかを聞かれます
6. 単元を解き終えたら、Git に保存するコマンドが案内されます
7. 「もう1問 解きますか？」と聞かれます（ウィンドウ版はボタン）。`y` なら、同じ言語の続きを1問出します（何回でも）。ウィンドウ版は、練習のあとでも、このボタンと「難易度を下げる」が出ます

### 途中でやめたとき・休みの日

- 途中でやめた（Ctrl+C やウィンドウを閉じた）ときは、答えていない問題が残り、**次に起動したとき、その問題だけが出ます**
- 設定の `days` にない曜日（既定は日曜）は、「今日は休みの日です」と出ます。ウィンドウ版では、休みの画面から「もう1問」で1問だけ解けます（「難易度を下げる」も使えます）。文字の画面は、通知からの起動を止めないよう、聞かずに終わります
- 土曜は「長めの読解」の問題が1問増えます（設定で曜日の変更・なしにできます）

### 練習（進み具合を使わない）

好きな単元を、記録に残さずに試したいときです。

- 文字の画面：`python drill.py questions/sql/batting_01_select.yaml`
- ウィンドウ：開始の画面で「練習」の言語と単元を選びます

## 言語の選び方

**今日の言語は、自動で決まります。** 学習した日の数（`data/log.csv` で数えます）と、設定の `languages`・`language_rotation` から決まり、同じ日に2回起動しても同じ言語です。

使う言語を決めるのは `config.yaml` です（`config.example.yaml` をコピーして作ります。なくても動きます）。

### 例1：Python だけ使う

```yaml
languages: [python]
```

### 例2：Python と SQL を1日ごとに交代する（同梱の見本の既定）

```yaml
languages: [python, sql]
```

`languages` を書かなければ、`questions/` にある言語をすべて、名前順で1日ずつ交代で使います。

### 例3：SQL は3日に1度にする

```yaml
languages: [python, sql]
language_rotation:
  sql: 3
```

`sql: 3` は「学習日の3日目、6日目、…は SQL。ほかの日は `languages` の先頭の言語」です。`sql: 1` なら毎日 SQL です。

### 例4：新しい言語（JavaScript）を足す

1. `questions/javascript/` というフォルダを作ります（フォルダ名が言語の名前になります）
2. 中に問題集（YAML）を置きます。作り方は[問題集を増やす](#問題集を増やす)を見てください（AI に作らせられます）
3. 採点のきまり `questions/javascript/_language.yaml` を作ります（大文字・小文字を区別するか、など。AI に作らせる指示文は `prompts/generate_language.md` です。なくても動きます）
4. `config.yaml` の `languages` に足します

```yaml
languages: [python, sql, javascript]
```

5. `python drill.py --check` で、形式の誤りがないかを確かめます

### 今すぐ別の言語をやりたい

- 練習（上の「練習」）で、言語と単元を選べます
- 今日の言語を変えたいだけなら、`language_rotation` を変えてください（記録の日数で決まるので、起動のたびに変える機能はありません）

## 設定（config.yaml）

`config.example.yaml` を `config.yaml` という名前でコピーして書き換えます。**書かなかった項目は、既定の値になります。**

| 項目 | 既定 | 内容 |
|---|---|---|
| `days` | 日曜以外 | 学習する曜日。例：`[mon, tue, wed, thu, fri]`（月〜金だけ） |
| `languages` | 自動 | 使う言語（`questions/` のフォルダ名） |
| `language_rotation` | 順番に回す | 言語の切り替え。例：`sql: 3` |
| `questions_per_day` | `2` | 1日の問題数（1以上の整数） |
| `level_up_streak` | `2` | 全問正解が何日続いたら、難易度アップを提案するか |
| `long_day` | `sat` | 長めの読解の問題を出す曜日。`none` で出さない |
| `notifier` | `none` | 通知の部品：`none` / `windows` / `email` / `ntfy` |
| `privacy` | `strict` | `strict`（PCの外に出る機能は使えない）/ `standard` |

曜日の名前は `mon tue wed thu fri sat sun` です。書き間違えると、起動時に分かる文章でエラーになります（落ちません）。

## 難易度のしくみ

- 難易度は Lv1〜5 で、**言語ごとに**持ちます。同じ単元でも、今の難易度以下の問題が先に出ます（絞り込みではなく、優先順位です）

| Lv | 内容 |
|---|---|
| 1 読む | 1行のコードの意味や結果を選ぶ |
| 2 埋める | 2〜3行のコードの空欄を埋める |
| 3 組み合わせる | 空欄2か所、または前に学んだ文法と組み合わせる |
| 4 間違いを探す | 動かないコードの間違いを選ぶ・直す |
| 5 実務寄り | 小さな処理を完成させる。長めのデータを読み解く問題を含む |

- 全問正解の学習日が `level_up_streak` 日続くと、終わった直後に「上げますか？ [y/N]」と聞かれます（`n` なら、連続を数え直します）
- 自分で上げる：`python drill.py --level-up`（言語が複数なら `--level-up python`）
- 自分で下げる：`python drill.py --level-down`（簡単すぎる・難しすぎるときに。ウィンドウでは、結果の画面にボタンがあります）
- 出題の順番：①答えていない問題 → ②今の周回で未出題 → ③直近で不正解 → ④正解。単元の全問を出したら次の単元へ進み、最後の単元のあとは「周回」が1つ増えて最初に戻ります

## 問題集を増やす

問題集は `questions/<言語>/` の下の YAML ファイルです。1ファイルが1単元で、ファイル名の番号順に出題されます（例：`u01_variables.yaml`、`u02_loops.yaml`）。

### AI に作らせる手順（5分）

1. `prompts/generate_questions.md` を開き、「指示文」の部分（````text で囲まれた所）をコピーします
2. AI（Claude・ChatGPT など）のチャットに貼り付け、`{言語}` `{単元}` `{難易度}` `{問題数}` `{既習の内容}` の5か所を書き換えて送ります
   - 例：言語は `javascript`、単元は「変数と四則演算」、難易度は `2`、問題数は `4`、既習の内容は「なし」
3. AI が出した YAML を、前後の説明を除いて、`questions/javascript/u01_variables.yaml` のように保存します（文字コードは UTF-8）
4. `python drill.py --check` で形式を確かめます。誤りがあれば、ファイル名と問題の番号つきで出るので、そのメッセージを AI に貼って「直して」と頼みます
5. 新しい言語のときは、`config.yaml` の `languages` に足します（[言語の選び方](#言語の選び方)）
6. `python drill.py` で出ることを確かめます

`{既習の内容}` に、すでに学んだことを書くと、それを組み合わせた問題を作ってくれます（簡単すぎる問題が減ります）。学習が進むたびに、書き足してください。
指示文には、Claude 版で毎日使っている出題の決まり（答えを見出しに書かない、同じ文法を続けない、計算問題にしない、コードは5行以内、難易度の下限、送る前の見直し、など）が入っています。

**AI が作った問題は、正しいとは限りません。答えと解説は、自分でも確かめてください。**

### 問題の形式（自分で書くとき）

```yaml
- id: py-var-001            # 問題の番号。ほかの問題と重ならない文字（言語をまたいでも）
  unit: 合計金額を求める      # 単元の見出し（答えは書かない）
  level: 1                  # 難易度（1〜5の整数）
  type: choice              # choice（選択肢）か blank（空欄）
  question: 空欄に入る記号はどれですか？
  code: |                   # 空欄は ___（アンダースコア3つ）
    total = 1200 ___ 300
  choices: ["+", "-", "*", "/"]   # choice のときだけ。4つがおすすめ
  answer: "+"               # 必ず引用符で囲む（囲まないと NULL や yes が別の型になります）
  explanation: 足し算は + です。
  hint: 合計は、あわせた数です。      # 任意
  long: true                # 任意。長めの読解の問題（土曜に1問出る）
```

- 必須の項目は `id` `unit` `level` `type` `question` `code` `answer` `explanation` です
- 検査（`python drill.py --check`）は、起動のたびに出題の前にも自動で行われ、誤りがあれば出題せずに止まります

## 通知（任意）

決まった時刻に、「今日の学習の時間です」と知らせる機能です。**使わなくても学習はできます。**

- `python notify.py --when start`：学習の時間の合図（学習する日だけ）
- `python notify.py --when remind`：**今日の記録がまだないときだけ**のリマインド（学習する日だけ。記録があれば何も送りません）
- 送る文章は「今日の学習の時間です（2問）」のような決まった一文だけです。問題・正誤・記録の中身は含みません

### どの部品を使うか

| 部品 | 内容 | 必要なもの | PCの外に出るか |
|---|---|---|---|
| `none` | 何もしない（既定） | なし | 出ない |
| `windows` | 画面の右下に通知（Windows だけ） | なし | 出ない |
| `email` | メールを送る | メールサーバーの設定（`.env`） | 出る（`privacy: standard` が必要） |
| `ntfy` | スマホにプッシュ通知（ntfy アプリ） | スマホの ntfy アプリ、送り先の名前（`.env`） | 出る（`privacy: standard` が必要） |

どれを使うかは `config.yaml` の `notifier` で決めます。

### 手順A：Windows の右下の通知（いちばん簡単。PCの外に出ない）

1. `config.yaml` に書きます

```yaml
notifier: windows
```

2. **まず手で試します**（通知が右下に出れば成功です）

```
python notify.py --when start
```

3. 決まった時刻に自動で出すには、Windows の「タスク スケジューラ」に登録します。コマンドで登録するなら、PowerShell で次を実行します（`C:\code-drill` は、このフォルダの場所に書き換えます）

```
schtasks /Create /SC DAILY /ST 17:30 /TN "code-drill 合図" /TR "python C:\code-drill\notify.py --when start"
schtasks /Create /SC DAILY /ST 21:30 /TN "code-drill リマインド" /TR "python C:\code-drill\notify.py --when remind"
```

   - 休みの日は `notify.py` が何も送らないので、「毎日」で登録して大丈夫です
   - `python` で動かないときは、`python.exe` の場所をそのまま書きます（`where python` で分かります）
   - 画面で登録したいときは、スタートメニューの「タスク スケジューラ」→「基本タスクの作成」で、プログラムに `python`、引数に `C:\code-drill\notify.py --when start` を指定します

### 時刻を変える・確認する・やめる

```
schtasks /Query /TN "code-drill 合図" /V /FO LIST      # 登録の内容（次回の実行時刻など）を見る
schtasks /Change /TN "code-drill 合図" /ST 18:00       # 時刻を 18:00 に変える
schtasks /Run /TN "code-drill 合図"                    # 今すぐ1回実行して試す
schtasks /Delete /TN "code-drill 合図" /F              # 登録をやめる
```

- 「合図は夕方、リマインドは夜」の使い分けがおすすめです。リマインドは、記録がある日は鳴りません
- パソコンにログインしている間だけ動きます（スリープ中・電源オフの間は動きません）

### 手順B：スマホに通知する（ntfy）

1. スマホに「ntfy」アプリを入れ、**推測されにくい名前**（10文字以上の英数字・- ・_。例：`my-drill-8f3k2x9q`）を購読します（知っている人は誰でも読めるので、名前は人に教えないでください）
2. `.env.example` を `.env` という名前でコピーし、書きます

```
DRILL_NTFY_TOPIC=my-drill-8f3k2x9q
```

3. `config.yaml` に書きます

```yaml
notifier: ntfy
privacy: standard
```

4. 手で試します：`python notify.py --when start`（スマホに届けば成功です）
5. 時刻は、手順A と同じ「タスク スケジューラ」で決めます。Mac・Linux では `cron` を使います。例（月〜土の 17:30）：`30 17 * * 1-6 python3 （このフォルダの場所）/notify.py --when start`

### 手順C：メールで通知する

1. `.env` に書きます（Gmail なら「アプリ パスワード」を使います。ふだんのパスワードは使いません）

```
DRILL_SMTP_HOST=smtp.gmail.com
DRILL_SMTP_PORT=587
DRILL_SMTP_USER=あなた@gmail.com
DRILL_SMTP_PASSWORD=アプリパスワード
DRILL_MAIL_FROM=あなた@gmail.com
DRILL_MAIL_TO=あなた@gmail.com
```

2. `config.yaml` に `notifier: email` と `privacy: standard` を書き、手で試します（`python notify.py --when start`）

### 通知が来ないとき

1. 手で `python notify.py --when start` を実行して、エラーが出ないか見ます（エラーの文章に、足りない設定の名前が出ます）
2. 日曜（休みの日）に実行していませんか？ `python notify.py --when start --date 2026-10-14`（水曜）で、休みの日以外として試せます
3. `--when remind` は、今日の記録があると何も送りません（正しい動きです）
4. `privacy` が `strict`（既定）のままだと、`email`・`ntfy` は使えません（エラーでそう出ます）
5. タスク スケジューラの登録を `schtasks /Query` で見て、「次回の実行時刻」が合っているか確かめます

## 個人情報と秘密情報

- 学習の記録（`data/`）と、個人の設定（`config.yaml`）、パスワード類（`.env`）は、**Git に上がらないようにしてあります**（`.gitignore`）
- 自作の問題集を Git に上げたくないときは、`.gitignore` に `questions/<言語>/` のように書き足します
- `privacy` の既定は `strict` で、PCの外に出る機能（`email`・`ntfy` の通知）を使えません。使うときは `config.yaml` に `privacy: standard` と書きます
- パスワードやトークンは、`.env` にだけ書きます（見本は `.env.example`。コピーして使います）。`config.yaml` に書くとエラーになります
- `.env` が Git に上がってしまう状態のとき、`notify.py` と `notion_sync.py` は何も送らずに止まります
- 一度でも Git に上げてしまったパスワードは、あとから消しても履歴に残ります。**そのパスワードを変更してください**
- 「情報が外に漏れることは絶対にない」とは言い切れません。`strict` なら外に出る情報はありませんが、`standard` ではメール・ntfy のサーバーに、決まった一文と送り先が渡り。ntfy は、送り先の名前（topic）を知っている人なら誰でも読める仕組みなので、推測されにくい名前にしてください

## 試験

```
python run_tests.py
```

全部の試験を実行して、試験仕様書と結果報告書（`docs/`）を作ります。試験が1つでも失敗すると、0 以外の終了コードで終わります。
コードや問題集を変えたあと、公開の前、別のPCで使い始めるときに実行してください（毎日の学習では要りません）。
GitHub に上げると、Windows と Linux の両方で、自動で試験が動きます（`.github/workflows/tests.yml`）。

## 困ったとき

| 困りごと | 対処 |
|---|---|
| `python` が見つからない | Python を入れ直し、「Add python.exe to PATH」にチェックを入れます。`py drill.py` で動くこともあります |
| `No module named yaml` | `python -m pip install -r requirements.txt` を実行します |
| 「エラー：問題集に誤りがあります」 | `python drill.py --check` で、誤りの場所が出ます。直すか、AI に貼って直してもらいます |
| 「記録ファイルに書き込めません」 | Excel などで `log.csv` を開いていませんか？ 閉じてから、もう一度実行します |
| ウィンドウ版が開かない | tkinter が入っていない Python です。文字の画面を使うか、python.org の Python を入れます |
| 休みの日なのにやりたい | ウィンドウ版は、休みの画面の「もう1問」で1問できます。たくさんやりたいときは、練習を使うか、`config.yaml` の `days` に曜日を足します |
| 同じ問題ばかり出る | 単元の問題が少ないためです。問題集を増やします（[問題集を増やす](#問題集を増やす)） |
| 最初からやり直したい | `data/` フォルダの中の `progress.json`（進み具合）と `log.csv`（記録）を、別の場所に移します |

## ファイルの構成

| ファイル | 役割 |
|---|---|
| `drill.py` / `gui.py` | 画面（文字・ウィンドウ） |
| `session.py` | 学習の流れ（画面を使わない部品） |
| `loader.py` `checker.py` | 問題集の読み込みと形式の検査 |
| `grading.py` `picker.py` `timetable.py` | 採点、出題する問題の選択、日程と言語の決定 |
| `history.py` `progress.py` `recorder.py` | 記録の集計、進み具合、記録の読み書き |
| `config.py` | 設定の読み込み |
| `notifier.py` `notify.py` | 通知の部品と、通知を出す入り口 |
| `prompts/` | AI に問題集（`generate_questions.md`）や言語の設定（`generate_language.md`）を作らせる指示文 |
| `questions/` | 問題集（1言語＝1フォルダ） |
| `data/` | 記録・進み具合（自分のPCだけ。Git に上がらない） |
| `tests/` `docs/` | 試験と、その仕様書・結果報告書 |

## 制限（確かめられていないこと）

確かめたこと：

- Windows（Python 3.10）と Linux（Python 3.13）で、全部の試験（`python run_tests.py`）が通ります
- ウィンドウ版の**見た目**（色・配置・文字の大きさ・日本語の表示）を、作った人のPCで確かめました

**未確認**のこと（偽の送り先・偽のデータでの試験までです。使う人が、自分の環境で確かめてください）：

- Windows の右下の通知が実際に表示される様子、本物のメールサーバー、ntfy のサーバーとスマホのアプリへの送信
- Mac での動作

そのほか：

- 通知は、パソコンが起きていて、ログインしている間だけ動きます
